## Findings considered and rejected

Recorded so future audits don't re-litigate them:

- **"Jobs double-completed after failure" (sync-engine catchAll)** — false positive: the catchAll path returns empty `invited`/`removed`, making the completion condition false. The real defect is the stuck-`running` job, covered by plan 003.
- **"`status as 400` hardcodes all error responses to 400"** — false positive: a TypeScript cast doesn't change runtime values. The cast is removed incidentally by plan 005.
- **"Audit-log inserts not awaited (silent failures)"** — false positive: every `db.insert(auditLog)` in `routes/{users,teams,repos}.ts` is `await`ed.
- **"Atlassian delete URL malformed" (`api-client.ts:234`)** — `https://api.atlassian.com/users/{account_id}/manage/lifecycle/delete` is the documented Atlassian user-management lifecycle endpoint; not a bug.
- **Sync-endpoint DoS via unbounded job creation** — mostly mitigated: the 409 dedupe check caps the queue at one pending/running job per type. Auth (plan 006) closes the rest.
- **Stale Google auth singleton in BFF routes** — `google.auth.GoogleAuth` refreshes tokens automatically; not a real defect.
- **PII (emails/usernames) in logs and Slack notifications** — intentional product behavior for an internal admin/audit tool; not worth doing.
- **"Invite race when a user is deleted mid-sync"** — already handled gracefully (error accumulated, sync continues); noise.
